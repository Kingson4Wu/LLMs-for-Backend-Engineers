# LLM 外部连接：Agent 运行时与控制设计

## 目标

让读者从全局理解 LLM 如何通过上下文、检索和工具连接外部世界，以及为什么可信系统还需要一个运行时来控制、验证和停止反馈循环。内容以原理、职责边界和选型为中心，不写成 Agent 框架或 MCP 协议手册。

## 全局结构

第三层维持四篇文章的递进关系：

```text
上下文与记忆：本轮输入从哪里来
        ↓
RAG 与知识库：外部资料怎样成为依据
        ↓
工具调用与 Agent：模型怎样请求外部能力
        ↓
Agent 运行时：系统怎样控制、验证并结束反馈循环
```

模型生成的是下一步建议。应用运行时拥有状态、秘密、权限、工具执行、观察结果、资源限制、审批与任务完成判定。外部程序和真实环境的结果，才是系统判断是否完成的依据。

## 新增文章：Agent 运行时：让反馈循环可控

文章按以下顺序展开：

1. 从“模型能调用工具”到“系统能够可靠完成任务”的缺口。
2. 固定工作流与 Agent 的控制流差异；链式、路由、并行和评审只作为四种简洁的组织方式。
3. 运行时控制循环：目标与状态、模型提议、策略检查、执行与观察、状态更新、终止或继续。
4. 可靠性边界：结构、语义、授权与执行结果分别校验；限制轮次、时间、成本和并发；高影响动作需要审批；记录可追溯事件并用任务结果评估。
5. 多 Agent 只在独立任务、独立能力或独立验证带来可衡量价值时使用；反思、记忆和重试改变运行时行为，不代表模型参数已学习。

不引入具体框架 API、内部调度器、MCP transport、GraphRAG 或长任务协议细节。

## 现有文章修改

### 工具调用与 Agent

保留工具声明、结构/含义/许可/结果四层和 Agent 循环。补充两点：

- MCP 是连接工具、资源和提示等能力的协议层；它不授予业务权限，也不负责业务正确性。协议的授权能力与可选扩展会随版本和客户端支持变化。
- “反思”“失败后重试”“写入记忆”是本轮或后续运行时适应；除非进入训练并更新参数，不称为模型学习。

### RAG 与知识库

增加“固定 RAG 与 Agentic RAG”的短节：固定 RAG 由程序决定一次检索链；Agentic RAG 允许模型在反馈下选择或重复检索、改写查询、补充资料或停止。后者只在问题路径难预先写死且额外观察能提高结果时值得采用；更多检索轮次不自动提高依据质量。
