# Transformer 笔记融入与内容规范设计

## 目标

将参考笔记中有助于建立因果链的内容融入本书，同时保持本书面向后端工程师的全局视角。读者应能区分 Transformer 的模型架构、训练稳定性和运行时执行，而不需要学习内核实现或完整训练配方。

## 内容边界

本次不新增长篇工程专题，不重排目录，不复制参考笔记的原文。聚焦更新现有 Transformer、Attention 和生成机制文章，并同步英文镜像。涉及训练和系统的细节仅用于说明架构决策的边界。

## 规范组件

在仓库根目录新增 `BOOK_CONTENT_GUIDELINES.md`，作为所有书籍内容的写作和复核规范；`AGENTS.md` 仅保留执行入口。规范将把以下原则变成具体检查项：

1. 先交代章节在全局链路中的位置。
2. 先给直觉与因果，再给必要的形式化细节。
3. 在关键机制处解释数据流、约束、作用与未解决的问题。
4. 明确模型架构、训练过程和运行时系统之间的边界。
5. 以有条件的表述替代将经验写成定律的表述。

## 文章修改设计

### Transformer 架构

在现有 RNN 对比前补充“为什么需要这种架构”的短段：序列建模从固定窗口、递归状态走向内容寻址；Transformer 缩短可见位置之间的信息路径，并让已知序列中的位置计算可并行组织。保留标准稠密注意力对序列长度的平方成本。

增加一个三层对照表。它将把 Attention、Mask、FFN、残差和归一化归入架构；将优化器、Warmup 和精度归入训练；将 Prefill、Decode、KV Cache 归入运行时。表格只定位职责，并链接各自的主文章。

### Attention 机制

保留 Q/K/V 的动态聚合类比，但收紧为“帮助理解，不是逐 token 的网络请求”。补上缩放点积的最小因果说明：维度增大时分数尺度会增大，缩放使 Softmax 不易过度饱和；Q/K 决定权重，V 被聚合。多头只描述为多个可学习投影子空间，不承诺每个头对应固定语言功能。

### 生成机制

在 Prefill、Decode、KV Cache 一节增加与三层对照的回链：KV Cache 复用因果注意力中的已计算状态，不是模型架构定义，也不是应用层长期记忆。保留缓存不能消除新 Query 与历史 Key/Value 的计算和内存成本的解释。

## 验收

- 用书籍校验器检查两种语言的链接和目录。

- 构建网页并运行既有网页检查与测试；若改动影响排版，再检查桌面与移动端页面。
- 检查术语边界：不把 FlashAttention、KV Cache、Warmup 写成 Transformer 的定义；不将训练经验表述为无条件规律。
