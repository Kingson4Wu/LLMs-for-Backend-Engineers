# “模型的能力是怎样训练出来的”章节调研

日期：2026-09-25。状态：调研结论；未修改书籍正文。

审查对象：[model-training-lifecycle.md](../../book/chapters/part2-llm-internal/model-training-lifecycle.md)。本笔记只采用原始论文或模型团队的技术报告作为外部依据，目的不是给出训练配方，而是判断该章是否足以让读者建立正确的训练全景。

## 结论

这章的中心链条是成立的，也比一般“预训练 → SFT → RLHF”流水线式介绍更准确：它已经区分了训练和推理、预训练和 SFT 的信号、偏好与可验证奖励、RLHF 与 DPO，以及数据污染和泛化之间的边界。它不需要重写成训练工程章节。

但它还缺少三个会影响读者全局理解的连接点：**参数从哪里开始、数据以什么方式成为训练输入、以及训练如何靠独立评测决定是否保留一次更新**。另应补一段说明：模型大小、训练 token 与可用算力是共同约束，参数量不能单独解释能力。这样读者才能把第一部分的“损失—梯度—优化器”连成一条完整但不过度细节化的训练闭环。

建议将新增量控制在约 3 个短节和 1 张概览图，不新开“训练基础设施”章节。

## 应补入本章的内容

### 1. 在开头补出“训练从什么状态开始”

当前图从“数据 → 模型输出”开始，读者仍可能看不出参数为何会从无意义的初值变成有用表示。建议在“先区分训练与推理”之后用两三句补齐：预训练通常从随机初始化的参数开始；继续预训练和后训练则从已有 checkpoint 开始。无论起点是什么，数据与目标只通过反复的前向计算、损失或奖励目标、反向传播和优化更新改变参数。

这不是重复反向传播章节，而是把那里解释的局部更新放回模型生命周期。它还可以自然引出 checkpoint：一次训练运行产生的是多个不同阶段的参数快照，后续评测决定哪些快照值得继续使用或发布。

### 2. 增加“资料不是直接倒进模型”的最小数据链

现有“数据怎样决定能力”强调覆盖和污染，但没有说明“原始资料”怎样变成可学习样本。建议加一个极短的、避免实现细节的图：

```text
原始资料 → 选择、清理与去重 → token 化、切分与混合 → 训练批次
                                                        ↓
                                  目标信号 ← 模型输出 ← 参数快照
                                                        ↓
                              独立评测/人工审查 → 继续、调整或停止
```

每个箭头只解释职责：选择和清理决定反复暴露什么；token 化和切分把资料变成模型可计算的序列；混合决定不同来源相对出现频率；训练集以外的评测检查更新是否在目标条件上变好。无需讲网页抓取、去重算法、数据配比或 batch 代码。

OLMo 的公开训练材料可验证这不是额外的工程枝节：其论文将训练数据、训练代码和评测代码作为同一套可审查对象发布；文中还说明文档被串接、按 token 长度切成训练实例并按确定顺序组成批次。[Groeneveld et al., 2024](https://arxiv.org/abs/2402.00838)。Llama 3 的技术报告也把数据质量、多样性和来源配比列为预训练的关键变量，并记录了过滤、去重和数据混合的做法。[Grattafiori et al., 2024](https://arxiv.org/abs/2407.21783)。这支持在本章解释“数据经过处理才成为样本”，但不支持把某个具体处理流程写成通用标准。

### 3. 把“数据决定能力”改为共同约束，并加入规模取舍

标题“数据怎样决定能力”有表达过满的风险。建议改为“数据塑造能力，也限制结论”，并在段首明确：架构与参数规模决定可表示和计算的范围，数据及其目标信号决定训练压力来自哪里，训练 token 数与可用算力限制实际能走多远；它们共同影响结果。

只需一个不带数字的结论：**在固定训练算力下，增大参数而不给足训练 token，并不天然更好。** Chinchilla 在其受测 Transformer 设定中发现，计算最优时模型规模和训练 token 会随算力共同增长；该结论是特定实验与目标下的缩放结果，不应写成所有模型的固定比例或当代训练配方。[Hoffmann et al., 2022](https://arxiv.org/abs/2203.15556)。

这段能校正“模型有多少参数 = 模型学到了多少”的直觉，也能为第四部分的算力与服务成本埋下边界，而不进入分布式训练。

### 4. 把验证放回训练闭环，而不仅是污染警告

现有末段正确地说明了训练集污染会夸大评测分数。还应把它上升半步：训练损失服务于训练目标，独立验证和任务评测服务于选择 checkpoint、发现退化和判断是否值得继续。二者不能互相替代；验证集也不是“绝对干净”就自动等于真实世界能力。

这只需要一小段，重点是因果位置，而不是 benchmark 名单、统计检验或线上 A/B 实验。OLMo 将训练和评测一并发布，正说明可复核训练结论至少需要看到两侧；InstructGPT 的人类偏好评测也显示“优化哪种偏好、由谁评价”是结果解释的一部分，而不是模型内在的普遍价值。[Groeneveld et al., 2024](https://arxiv.org/abs/2402.00838)，[Ouyang et al., 2022](https://arxiv.org/abs/2203.02155)。

### 5. 在偏好节补一个术语边界即可

可加一句：偏好数据可以来自人工比较、程序验证器或经过审查的合成样本；它们是**训练信号的来源**，不是新的必经训练阶段。若资料来自模型生成，仍需要由人或独立规则决定怎样筛选、比较或验证。Llama 3 的后训练报告同时记录了合成数据的使用，以及直接用最强模型自生成数据可能使表现退化、因而需要执行反馈和筛选的经验。[Grattafiori et al., 2024, §4.3](https://arxiv.org/pdf/2407.21783)。这样可防止读者把“合成数据”误解为模型自行可靠学习，也不需要另开“合成数据”节。

## 需保留或微调的事实边界

1. 章节以“自回归语言模型的常见预训练任务”为限定是必要的。不要把“预测下一个 token”改写成所有模型、所有模态唯一的预训练目标。
2. “数据决定能力”应避免单因果措辞。数据很关键，但训练结果也受架构、参数规模、优化、算力和评测方式影响；Chinchilla 的结果正是反例证据。
3. “模型选择工具”只表示模型能学习生成调用格式或选择意图；真正执行外部操作的是第三部分的运行时和工具系统。否则容易误把参数训练说成获得系统权限。
4. DPO 节的核心事实无误：原始 DPO 目标直接利用偏好对，并避免单独的奖励模型和该算法训练循环内的在线采样。不要将此推广为“所有偏好优化都不需要奖励模型”或“DPO 不需参考模型”。
5. 奖励、偏好与验证器反映的是被提供的评价函数或标注群体，不自动等于事实正确性或普遍的人类价值。现有章节已经说到这一点，建议保留。

## 建议的最小重排

不改变现有文章主顺序，只在其中插入：

1. 在“训练与推理”图后加入“参数起点与 checkpoint”。
2. 在“预训练”前加入数据进入训练的短图，或把它作为预训练首段。
3. 把“数据怎样决定能力，也限制结论”改名并加入参数—数据—算力共同约束。
4. 在该节末尾增加“训练目标与独立验证”的区分。
5. 在偏好节末尾用一句话放置合成数据和可验证奖励。

这样仍然是一篇解释“能力如何由训练信号形成”的文章，而不是一篇模型训练操作手册。
