# 内容定位与参考书选题分析

日期：2026-09-24。状态：选题建议，尚未修改正文或目录。

## 定位依据

用户明确：本书帮助读者清晰、全局地理解大模型，以贴近本质的方式解释原理；部分基础深入，但不过度进入大模型实现细节。这意味着扩充目标是补全概念之间的关系，而不是增加生产部署、应用框架或训练操作教程。

建议定位：面向有编程经验、缺少机器学习背景的读者，用必要的数学基础、模型机制和系统边界，解释大模型如何获得能力、如何生成输出，以及如何借助上下文与外部系统完成任务。

现有依据：[导读](../../book/index.md)、[前言](../../book/preface.md)、[目录](../../book/catalog.json)。18 篇正文分布为基础 10 篇、内部机制 7 篇、外部连接 1 篇。数量不用于要求各部分平均，只用于识别认知链条的缺口。

## 最值得新增的四篇

### 1. 模型的能力是怎样训练出来的

回答：从“预测下一个 token”到“遵循指令、回答问题、使用工具”，中间发生了什么？

- 先把训练与推理放在同一张图里：哪些阶段更新参数，哪些阶段使用既定参数。
- 用同一个小任务比较原始语料、示范答案和奖励/偏好信号。
- 建立预训练、SFT、偏好优化与强化学习的概念关系；不要将所有偏好优化等同在线 RL，也不要暗示每个模型必须走相同流程。
- 接回现有交叉熵、反向传播、微调与蒸馏，不重复推导。
- 继续预训练、LoRA 仅作概念旁注；不讲训练命令、超参数和算法实现。

位置：第二层开头，用全景连接第一层基础与后续结构。已有微调蒸馏篇负责比较适配和压缩，不另写重复入门。

依据：[第 8 章“四阶段全景”](../../../../github/ai-agent-book/book/chapter8.md)。正式写作不照搬该章“SFT 记忆、RL 泛化”等简化对立。

### 2. 上下文与记忆：模型这一轮究竟知道什么

回答：为什么多轮对话像有记忆？给模型一段资料和重新训练有什么不同？聊天、RAG 与长期记忆怎样相连？

- 区分参数中的学习结果、当前请求中的上下文、应用持久保存的数据。
- 用两轮对话展示：保存过的信息如何被选择并重新放入模型输入。
- 解释提示词、示例、历史消息、工具结果的作用；说明上下文学习与参数更新的区别。
- 解释窗口容量、有效利用、截断与摘要的取舍；不把单一注意力类比当作完整机制证明。
- 比较经验写入记录、指令、程序和参数，消除“聊久了模型就自动训练了”的混淆。

位置：第三层开头，衔接模型生成与 RAG。记忆不另开大型专题。

依据：参考第 2 章“消息的四种角色”“上下文压缩策略”、第 3 章“用户记忆系统”、第 9 章“持续进化的四种方法”。

### 3. 工具调用与 Agent：从生成回答到反馈循环

回答：生成 token 的模型为什么能查数据库、运行程序、完成多步任务？

- 用一条完整且短小的轨迹解释：声明工具 → 生成调用请求 → 程序执行 → 返回结果 → 继续生成。
- 区分结构/格式合法、参数含义正确、操作获准、执行成功；不把合法 JSON 当作正确答案。
- 在同一例子里比较单次调用、固定工作流、动态反馈循环。
- 简介外部运行层承担的状态、执行和终止职责；术语 Harness 可括注，无需独立专题。
- 用计算器或查询例子解释生成与执行的分工，再用一段说明多 Agent 的上下文分工与通信代价。
- MCP、Skill 只放术语关系框：说明接口与说明材料的位置，不教生态配置。

位置：第三层 RAG 之后。只需一张时序图、一条轨迹和少量伪代码，不引入框架。

依据：参考第 1 章“ReAct 循环”“编排模式”、第 2 章“带工具调用的多轮交互”、第 4 章“工具”、第 5 章“代码作为思考工具”、第 10 章“上下文是否共享”。

### 4. 能力边界与验证：为什么答得像样还不够

回答：怎样区分模型会生成、偶尔答对、稳定完成，以及系统确实完成？

- 从生成机制接到事实依据、幻觉与不确定性，不用一句“概率模型”解释所有失败。
- 比较单次正确、多次尝试至少一次正确、重复运行的一致性。
- 区分答案正确、引用支持、工具执行结果和业务任务完成。
- 用少量对照案例解释提示变化、检索质量和工具反馈如何影响结果。
- 简介模型评审也会出错；不展开评测平台。
- 将提示注入作为指令与外部数据边界的一个短例子，并与工具执行边界衔接。

位置：第三层末尾。与现有“AI 系统工程实践”合并重构，避免再增加一篇重复原则清单。

依据：参考第 7 章“成功的定义”“验证器”“失败归因”，第 2 章“提示注入”。

## 适合补入已有正文，而非另开长篇的内容

1. **Token 与消息格式**：当前从 One-hot/Embedding 到生成之间，补“文本 → token ID → 向量”以及角色边界的概念示意。参考第 2 章 Chat Template。Tokenizer 的合并算法不展开。
2. **Prefill、Decode、KV Cache**：扩生成篇，用短序列解释计算复用；不讲分页缓存、内核或推理服务部署。参考第 2 章缓存小节。
3. **推理文本与推理时计算**：在生成篇解释中间步骤、追加生成、重试和验证之间的关系，明确不同方法的边界。不要把“逐 token 生成”直接推导成“不可能推理”，也不要把可见推理文本等同内部计算的忠实记录。参考第 1 章 LLM/循环、第 5 章代码辅助、第 7 章多次尝试。
4. **RAG 原理完整链**：补文档切块、关键词与语义的互补、独立编码与联合匹配的区别、检索结果如何进入上下文。保留现有 Rerank 重点，但将优势写成条件性取舍。参考第 3 章 Chunking、稠密/稀疏与混合检索。
5. **多模态概览**：用一张示意图比较原生图像/语音输入与外部识别工具，并说明模型解释与实际动作的边界。第一轮可作为第二层末尾的可选短文；不将扩散模型、语音架构、机器人控制拉入正文主线。参考第 4 章多模态感知、第 6 章模态扩展。

## 深度标准

每个主题都要回答：输入是什么、发生了什么变化、输出是什么、状态在哪里、这能解释什么现象、解释到哪里失效。一个读者疑问、一张机制图、一个最小例子、一个反例，优先于术语目录和大段代码。

基础细节值得保留，当且仅当它能支撑后续概念：点积支撑匹配，Softmax 支撑分布，损失和梯度支撑训练，Embedding 支撑表示与检索。已有优化器、推导等可标为深入阅读，不必为篇幅均衡删除基础，也不要求所有读者逐篇读完才看到全景。

建议在导读增加一页全景图，先展示训练、推理、上下文和外部系统的位置，再进入三层正文。

## 不直接继承参考书的论断

- 第 5 章代码辅助实验的目标与章节实验 README 的实测结果存在区别：README 对 5-3 写明未达显著，对 5-4 写明代码臂未达到预期且低于对照。只借鉴生成—执行—反馈机制，不宣称代码辅助必然更强。
- 第 2 章将上下文学习概括为“检索而非推理”；本书不将此类机制解释当作所有模型的已证定论。
- 第 8 章的阶段表和 SFT/RL 类比适合启发选题，不能变成普遍能力分工、成本区间或固定训练配方。
- 第 10 章的信息增量视角适合提出问题，不应照搬为多 Agent 优势的唯一判据。
- 任何参考数字和厂商现状若需要进入正式正文，另查一手来源与条件；本轮不做这些事实的外部审定。

## 内容工作顺序

1. 先修现有生成、Transformer、RAG 和基础例子的技术表述；[英文审校记录](../../book/translations/en/review-notes.md)已有问题线索。
2. 补导读全景、训练全景与上下文/记忆，先贯通模型内外。
3. 扩 RAG，加入工具/Agent 原理，重构能力边界与验证。
4. 最后决定多模态短文是否独立；多 Agent、MCP、Skill 保持短节。
5. 每次正文变化同步英文和来源状态，避免中文与英文保留不同技术结论。

建议净新增三篇核心正文（训练全景、上下文/记忆、工具/Agent），将能力边界并入现有工程实践篇；多模态一篇可选。这样预计从 18 篇变为 21–22 篇，最终篇数以解释完整、避免重复为准。
