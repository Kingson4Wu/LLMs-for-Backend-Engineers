# 模型的能力是怎样训练出来的

一套大模型会不会解释代码、遵循指令、可靠地调用工具，并不取决于某一个叫作“训练”的黑盒。它来自一条完整的因果链：**给模型什么资料，模型怎样计算，什么结果算好，误差怎样回传，参数怎样更新，以及最后怎样验证。**

交叉熵衡量预测误差，反向传播把误差分配到参数，优化器把梯度变成实际更新。本章把这些组件放进同一个训练系统，说明它们怎样一起把资料中的规律变成模型参数，以及这些参数为什么既会形成能力，也会留下边界。

## 先看训练的全景

先把训练和推理分开。推理使用已有参数，根据当前上下文生成下一个 token；训练则反复用数据检验输出，再改变参数。生成文字并不是分界线：训练过程也可能生成候选答案。真正的分界是，**这次计算是否根据训练目标更新了参数。**

```text
原始资料、示范或反馈
          │
          ▼
选择、清理、去重、混合、token 化
          │
          ▼
      一个训练批次
          │
          ▼
Transformer 前向计算 ──→ 每个位置的词表分数（logits）
          │                              │
          │                              ▼
          │                         训练目标 / 损失
          │                              │
          │                              ▼
          └──── 模型结构与参数 ← 反向传播 ← 梯度 ← 优化器更新
                                     │
                                     ▼
                              新 checkpoint（参数快照）
                                     │
                                     ▼
                         独立验证与任务评测：继续、调整或停止
```

这张图里有六个不同职责，混在一起就很容易误解训练。

| 组件 | 它决定什么 | 它不单独保证什么 |
| --- | --- | --- |
| 数据 | 模型反复接触哪些语言、事实、任务和错误模式 | 模型一定学会了正确规律 |
| 模型架构与参数 | 能怎样表示、组合和计算输入 | 需要什么行为就会自然出现 |
| 训练目标 | 什么输出会被鼓励、什么偏差会被惩罚 | 目标恰好等于人真正想要的质量 |
| 反向传播与优化器 | 误差怎样成为具体的参数改动 | 这次改动会在陌生任务上泛化 |
| 计算预算与训练过程 | 能看到多少数据、进行多少更新、是否稳定 | 更大参数一定更强 |
| 验证与评测 | 我们能观察到哪些进步和退化 | 分数代表全部真实世界表现 |

训练不是把资料逐条塞进一个可检索的数据库。参数会从大量例子中压缩出对未来预测有用的统计结构；它们不保留一份可以按主键查询、逐条核对出处的原文目录。

## 一次参数更新究竟发生了什么

以一句很小的文本为例：`一箱有 12 瓶水，3 箱共有 36 瓶。` 对自回归语言模型，前面的 token 是条件，后面的 token 是目标。模型不是直接输出“正确”或“错误”，而是在每个位置给整个词表一组分数。

```text
输入 token：一箱 有 12 瓶 水 ，3 箱 共有
目标 token：                         36 瓶 。

token ID → Embedding + 位置信息 → Transformer → logits → Softmax 概率
                                                     │
                                        目标 token 的概率太低？
                                                     │
                                                     ▼
                                               交叉熵损失
```

Tokenizer 把文字转成模型可处理的编号；Embedding 和 Transformer 把编号变成上下文化的表示；输出层把表示变成词表分数；交叉熵衡量真实后续 token 的概率是否足够高。架构决定这一次前向计算如何发生，训练目标决定这次结果怎样被评价，两者不是同一件事。

接着，反向传播从损失出发，计算每个可训练参数对这次误差的局部影响；优化器再根据这些梯度和自己的状态，给参数一个实际更新。更新后的参数进入下一批数据，循环数百万乃至更多次。

```text
一个批次
  → 前向计算：参数 θ 产生预测
  → 计算目标：预测与训练信号形成损失 L
  → 反向传播：得到 ∂L/∂θ
  → 优化器：θ ← θ - 一次受控制的更新
  → 下一个批次：用新 θ 再次检验
```

单个样本不需要“教会”模型乘法。许多不同表述中的数字关系、自然语言结构、程序模式和事实关联，会反复对相同的一部分参数施加方向相近或相互冲突的更新。能力是在大量更新后的整体参数状态中形成的，不在某一条训练样本里单独存放。

这也解释了训练与推理的边界。推理时，模型生成的 token 会被放回上下文，因而改变下一步预测；参数通常不变。让模型“再想一会儿”往往是增加推理步骤、搜索或工具使用，不是临时开了一次训练。

## 从资料到 checkpoint：训练是一个持续闭环

训练开始时，参数可能是随机初始化，也可能来自已有 checkpoint。预训练、继续预训练、监督微调和偏好优化常常共享后一个起点。Checkpoint 不是同一模型的不同名称，而是不同训练时刻的完整参数状态。

原始资料也不会原封不动进入批次。来源选择、清理、去重、质量过滤、语言与领域配比、切分长度和采样方式，共同决定哪些模式会被反复看见。对于预训练，文本本身就提供后续 token 目标；对于助手行为，则通常还要组织成“请求—回答”或“请求—多个候选—评价”的形式。

```text
资料与任务定义 → 数据处理与混合 → 批次 → 更新参数 → checkpoint
       ↑                                                  │
       └─────── 验证、任务评测、数据审查与训练监控 ────────┘
```

验证不是训练循环外的装饰。训练损失用于推动参数朝当前目标移动；独立验证和任务评测用于发现过拟合、选择 checkpoint、决定是否改变数据或目标。若测试题、答案或近似变体早已进入训练资料，分数无法区分模型是真的泛化，还是重复暴露过相似内容。

所以“模型已经学会 X”至少包含三个不同问题：训练资料是否覆盖 X，训练目标是否鼓励 X，以及独立测试是否真的在陌生条件下检查了 X。把这三件事压成一个训练损失或一个排行榜分数，结论通常会过头。

### 训练产物为何必须可追溯

对后端工程师而言，checkpoint 可以先类比为一个需要可追溯的发布产物，但训练并不是确定性的编译过程。数据版本或清洗规则变了、初始 checkpoint 不同、tokenizer 和训练代码不一致，甚至批次顺序、随机数、数值精度或硬件执行路径变化，都可能使最后参数和行为不同。只保存一个权重文件，通常不足以解释它为什么在某个任务上变好或退化。

因此，比较或发布一个训练结果时，至少应能关联其数据清单与处理方式、初始 checkpoint 和 tokenizer、代码与训练配置、优化和数值设置，以及独立评测的任务集和结果。目标不总是要求在不同硬件上逐 bit 重现同一组权重；更关键的是让团队能够解释候选版本来自什么条件、行为差异可能由哪里引入，并在出现回归时回到可比较的版本和证据。

## 同一骨架，三类不同的训练信号

预训练、监督微调和偏好优化并不是三台不同的机器。它们都沿用“前向计算 → 目标 → 梯度 → 更新”的骨架，主要区别在于输入如何组织，以及系统认为什么结果更好。

### 预训练：先形成广泛的预测能力

自回归预训练通常让模型根据前文预测后文。要在书籍、代码、问答、说明文和不同语言中持续做这件事，模型必须逐渐利用词义、上下文结构、事实关联和部分解题模式。大规模语言建模能产生广泛能力，正是因为“把后文预测得更好”要求模型在不同语境中提取可复用的信息。[GPT-3 论文](https://arxiv.org/abs/2005.14165)展示了这种训练与多种任务表现之间的联系。

但这条链不能被倒过来理解。训练损失下降不等于模型拥有完整、正确的世界知识，也不等于它每次都会可靠计算。它只是说明：在这类训练分布上，模型更擅长给真实后续 token 分配高概率。

预训练后的模型可以续写习题，也可以回答问题；可它学到的首先是“什么续文常常合理”，不一定是“怎样成为符合用户意图的助手”。后训练由此才有意义。

### 监督微调：示范希望它怎样回答

监督微调（SFT）把数据组织成更明确的任务。例如，输入是“每箱 12 瓶，3 箱共有多少瓶？”，示范答案是“$12 \times 3 = 36$，共有 36 瓶。”训练仍然是提高目标 token 的概率，只是通常主要计算回答部分的损失。

示范传递的不是“这段文字曾经出现过”，而是“面对这类请求，期望以这种方式回答”。它可以稳定输出格式、教模型说明依据、在信息不足时提问，或产出结构化的工具调用请求。[InstructGPT](https://arxiv.org/abs/2203.02155)中的人工示范就是这一类信号。

SFT 也不只是背诵答案。更新会同时影响表达方式、任务倾向和已有知识的调用方式；但样本覆盖狭窄时，它也可能过度贴近示范分布。全是整数算术示范，并不能证明模型能处理缺货、单位换算或题意不完整的情况。

### 偏好与奖励：当正确答案不止一种

有些任务不能为每个输入指定唯一的标准文本。两个答案都得到 36，其中一个解释了单位，另一个充满无关内容；此时更自然的信号是“在这个问题上，A 比 B 好”。偏好是相对评价，不自动等于事实真伪：流畅的错误答案也可能被偏好。

一种传统路线先根据比较数据训练奖励模型，再让语言模型生成候选，并使用强化学习提高奖励。InstructGPT 采用了“示范—比较—奖励模型—PPO”的具体组合。另一类奖励来自可验证结果，例如程序是否通过测试或最终数值是否正确；它们同样只能检查验证器实际覆盖的性质。

直接偏好优化（DPO）走的是另一条路：它在已有的优选／劣选回答对上直接训练语言模型，相对于参考模型调整两类答案的倾向，不需要先单独训练奖励模型，也不要求在训练循环内在线生成候选。因此，不能把所有偏好优化都叫作在线强化学习。[DPO 论文](https://arxiv.org/abs/2305.18290)说明了这一点。

| 信号 | 数据形状 | 它主要在改变什么 | 典型风险 |
| --- | --- | --- | --- |
| 预训练 | 大量 token 序列 | 广泛的表示、关联与预测模式 | 数据偏差、事实错误、重复暴露 |
| SFT | 请求与期望回答 | 指令跟随、格式和任务行为 | 示例覆盖窄、过度适配 |
| 偏好或奖励 | 回答比较，或候选与分数 | 多个可行回答之间的选择倾向 | 奖励投机、评价者偏差、验证遗漏 |

合成数据也可以进入任何一种流程，但“由模型生成”本身不是质量保证。它仍需要人工审查、独立规则或可验证结果来决定是否值得成为训练信号。

## 能力、规模与边界一起看

模型能力不能只归因于数据。架构和参数规模给出了可表示和可计算的范围；数据分布决定它接触哪些关联；目标规定哪些行为被鼓励；优化过程和计算预算决定这些信号能推动多少有效更新；评测决定我们最后能否看见真实进步。

参数更多也不等于训练得更充分。在给定计算预算下，模型大小和训练 token 数要共同取舍。Chinchilla 的实验表明，许多当时的大模型相对数据量而言训练不足；它是特定设定下的缩放实证，不是任何模型都照搬的固定比例。[Chinchilla 论文](https://arxiv.org/abs/2203.15556)

同样，后训练不能被理解成只给模型“润色语气”。它能显著改变模型在用户请求面前愿不愿意、怎样调用已有能力；但它的规模通常远小于预训练，也无法自然弥补从未覆盖的知识、工具环境和评价标准。反过来，预训练也不会自动决定一个系统在真实任务里是否可靠。

训练在这里结束，系统可靠性却没有结束。模型输出进入工具、检索、权限和评测闭环后，新的失败模式还会出现。本书第三部分讨论这些外部系统怎样为模型补充证据、行动能力与控制边界；下一篇[微调与蒸馏](fine-tuning-and-distillation.md)则继续讨论：当已有模型已经具备基础能力时，怎样以更小的训练代价适配它，或把教师模型的行为传给另一个模型。
