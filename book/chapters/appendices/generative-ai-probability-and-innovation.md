# 生成式 AI：概率生成、约束与验证

大语言模型根据当前上下文生成下一个 token。这一机制让它能续写、改写和组合大量语言模式，也让它在面对严格、全局或反常的约束时需要额外的结构。理解这点，比从一次“模型能不能写出怪句子”的测试推断人类与 AI 的本质差异更可靠。

## 概率生成回答什么问题

给定上下文 $x$，语言模型表示下一个 token 的条件分布：

$$
P(t_{next}\mid x)
$$

训练使模型在训练目标与数据条件下更好地估计这种分布；生成时，解码策略从中选择或采样 token。温度、top-p 等策略会改变候选的相对机会与随机性，却不会为模型自动提供一个外部词典、形式规则或事实验证器。

这带来两个常见现象：模型往往偏向训练中常见、在当前上下文中连贯的续写；而“避免所有词典中的二字词”“输出必须满足 JSON Schema”“结论必须被实验支持”这类要求，约束的对象是整段输出或外部世界，不能仅靠每一步局部选择稳定保证。

```text
上下文 ──→ 下一个 token 的分布 ──→ 解码 ──→ 候选输出
                                                   │
                                    规则、工具或评测器验证
                                                   │
                                         接受、修订或重新生成
```

## 一个反常约束实验能说明什么

设任务要求：只用常见汉字，生成一段整体混乱、并尽量避免常见二字词的文本。直接生成常会出现高频搭配；加入明确禁止项和示例后，模型可能转向“名词堆砌”等更容易满足表面约束的策略。

这个现象说明的是**约束遵循与验证的差别**：提示词能改变条件分布和模型偏好的策略，却不能替代一个明确评分器。它不能单独证明模型不会“反向思考”、人类一定更容易完成任务，或两者存在固定的认知鸿沟。结论取决于模型版本、tokenizer、提示、解码参数、允许的工具、词典与评分规则。

若要把这个任务变成有效评测，至少需要固定：

| 要素 | 为什么必须固定 |
| --- | --- |
| 常见字集合与词典 | “常见”和“有意义”并非天然边界 |
| 输出长度与允许例外 | 否则不同样本不可比较 |
| 解码与重试预算 | 多次采样和温度会显著改变通过率 |
| 自动评分器与人工复核 | 局部词典命中不等于整体有意义或无意义 |
| 是否允许工具 | 外部检索、程序检查会改变系统能力 |

## 提示词、结构化输出与验证各负责什么

提示词适合表达任务目的、上下文、例子和偏好；结构化输出适合限制语法和字段；验证器适合判断可计算的全局约束；工具适合查询事实或执行实验。把它们混为“提示写得够不够好”，会掩盖系统真正缺失的能力。

```text
目标与背景 ──→ 提示词
输出形状     ──→ Schema / grammar
可检验条件   ──→ 程序、词典、测试或检索
失败处理     ──→ 修订、重试、拒绝或交给人
```

例如，若要求所有相邻字都不在词典中，程序可以逐对检查；若要求内容真实，检索和领域证据比模型自述更重要；若要求风格“怪异”，仍需要人或经校准的评测标准判断。模型可以提出候选和修订方案，但验证闭环决定系统能否稳定交付。

## 概率不是能力与价值的判决书

“模型以概率生成”是机制描述，不是“模型只能复制”或“模型不能创新”的结论。低概率序列可以是噪声，也可以是有价值的新候选；高概率序列可以可靠，也可以陈词滥调。新颖性、正确性和价值需要不同证据。

同样，模型在一次任务上失败，可能源于提示歧义、解码方式、上下文不足、没有外部工具或评分器不合适，而不必然揭示其全部能力边界。好的评测应把任务、工具预算、验证标准和成功条件公开，使失败可以定位、成功可以复现。

## 模型对自身的解释也需要验证

模型可以流畅解释“我为什么这样回答”或“我使用了什么推理步骤”，但这类文本首先是一个生成结果，不是可直接读取内部状态的诊断报告。它可能来自技术语料、提示词要求的角色、事后合理化或对当前上下文的模式匹配；语言流畅不等于它描述了真实的因果过程。

与其把标准设为“人类能内省、模型不能”，不如问解释能否被独立观察、干预或复现。架构与实现文档能说明模型定义上怎样计算；激活测量、探针和可控干预可研究表示；输入消融、工具轨迹和版本记录可帮助解释某次输出；基准、真实任务评测和错误分析则回答系统是否可靠。模型的解释仍有用，它可以提出待检查的理由和下一步验证方向；高影响场景不能把“模型说它检查过”当作检查已经完成。

```text
模型解释 ──→ 可检验主张 ──→ 外部证据与工具验证 ──→ 决定是否采纳
```

## 小结

生成式 AI 的核心是条件概率建模和解码；这解释了它为什么能高效生成候选，也解释了为什么严格的全局约束需要结构化输出和外部验证。输出的自我解释也属于待验证的主张。把概率生成、提示约束与证据闭环放在一起看，能避免把一次有趣的失败实验误读为关于智能、创造或意识的最终结论。
